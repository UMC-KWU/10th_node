- OAuth 2.0
    
    OAuth 2.0은 사용자의 비밀번호를 직접 공유하지 않고도, 외부 애플리케이션이 제한된 권한으로 사용자 정보에 접근할 수 있게 해주는 인증/인가 프로토콜이다. 대표적으로 “구글 로그인”, “카카오 로그인” 같은 소셜 로그인이 OAuth 2.0 기반으로 동작한다.
    
    사용자는 서비스에 직접 비밀번호를 제공하지 않고, 인증 서버(Google, Kakao 등)를 통해 로그인한 뒤 Access Token을 발급받는다. 이를 통해 보안성이 높고, 사용자 입장에서도 여러 서비스에서 간편하게 로그인할 수 있다는 장점이 있다.
    
    다만 구조가 복잡하고, Access Token 관리나 Redirect URI 설정 등을 잘못하면 보안 문제가 발생할 수 있다는 단점도 존재한다.
    
- JWT
    
    JWT는 사용자 정보를 JSON 형태로 저장한 토큰 기반 인증 방식이다. 서버는 로그인 성공 시 JWT를 발급하고, 클라이언트는 이후 요청마다 이 토큰을 함께 전송하여 인증을 수행한다.
    
    JWT는 `Header`, `Payload`, `Signature` 세 부분으로 구성된다. 특히 Signature를 통해 토큰 위변조 여부를 검증할 수 있기 때문에 안정적으로 인증 처리가 가능하다.
    
    서버가 세션 정보를 별도로 저장하지 않아도 되므로 확장성이 좋고, REST API 환경에서 자주 사용된다는 장점이 있다. 반면 토큰이 탈취되면 만료 전까지 악용될 수 있어 만료 시간 설정과 보안 관리가 중요하다.
    
- Bearer Token
    
    Bearer Token은 HTTP 요청의 Authorization 헤더에 담아서 사용하는 인증 토큰 방식이다. 일반적으로 JWT를 Bearer Token 형태로 전달하는 경우가 많다.
    
    Authorization: Bearer {token}
    
    서버는 전달받은 토큰을 검증하여 사용자의 인증 여부를 확인한다. 구현이 간단하고 API 기반 서비스에서 많이 사용된다는 장점이 있지만, 토큰 자체만으로 인증이 가능하기 때문에 유출 시 보안 위험이 크다. 따라서 HTTPS 사용과 토큰 만료 정책이 중요하다.
